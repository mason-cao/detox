How should the Isle actually be drawn?

The biggest architectural call. Current build is a 5-column CSS grid of "plot" cards. Stardew feel needs a real world, not a grid of boxes. Three fidelity tiers — each unlocks different motion.

A

Polished CSS grid (Tier 1)

Keep the current rectangle-grid architecture. Add chunky pixel borders, hover lifts, hourglass overlays, ambient sparkles. Residents stay as emoji-in-boxes.

Effort: ~3 days. Touches CSS, no JS rewrite.
Ceiling: A nicer Habitica. Not Stardew. Honest about what's possible.
Motion unlocked: Hover, ambient bobs, currency-earn floats.
B

SVG isometric world (Tier 2) recommended

One SVG canvas. True iso projection. Buildings placed at fixed coords. Residents are sprite groups that walk between buildings on a path. Sky/weather are SVG layers above.

Effort: ~1.5 weeks. Replace web/js/isle.js renderer; CSS shrinks.
Ceiling: Genuine Stardew feel. Walking sprites, building doors that open, weather that touches the world.
Motion unlocked: Walk cycles, path animation, building hover wobble, smoke from chimneys, day/night light passes.
Constraint: Stays vanilla — SVG is just markup, no bundler needed.

Canvas game engine (Tier 3)

PixiJS or Phaser. Frame-rate animation, particle systems, full sprite atlases. Real game loop.

Effort: ~3 weeks + ongoing maintenance.
Ceiling: Best possible look.
Cost: Breaks "no build step / no Node" rule from CLAUDE.md. Adds 200KB+ runtime. Heavy for a screen-time tracker.
Honest take: Overkill for this project. Listed for completeness.

My strong recommendation is B. It's the smallest leap that gets you to "actually feels like a game" without breaking the no-build-step constraint. A is too modest for the C-scope you picked; C is too much.
